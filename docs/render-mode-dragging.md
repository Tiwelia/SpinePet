# SpinePet 渲染模式拖动设计与实现

## 目标

在不破坏配置模式精确编辑能力的前提下，为渲染模式增加自然的左键拖动交互，并整理迭代过程中遗留的重复状态和旧单角色协议。

完成后应满足：

1. 渲染模式下，左键短按角色播放 `action`。
2. 左键移动超过系统拖动阈值后进入拖动，不再触发 `action`。
3. 拖动开始时，从除 `idle`、`action` 外的动画中随机选择一个并循环播放；无候选动画时继续播放 `idle`。
4. 拖动结束后保存位置并返回 `idle`。
5. 点击或拖动角色时不会操作到角色下方的应用。
6. 配置模式的选框拖动、缩放和动画选择保持不变。
7. 100% 动画速度等于 Spine `timeScale = 1.0`，并能按角色持久化。
8. 用户可以全局关闭渲染模式拖动；关闭后短按互动仍然有效。

## 设计决策

### 输入状态机

低层鼠标 Hook 继续负责透明窗口上的可靠输入，并统一管理：

- `Pressed`：在角色命中区域内按下，记录屏幕坐标并请求 JS 做透明像素/层级命中。
- `Dragging`：目标角色已确定且位移超过系统拖动阈值。
- `Released`：未拖动则触发点击动作；已拖动则提交最终位置并恢复待机。

JS 负责角色精确命中和动画选择；C# 负责鼠标捕获、坐标变化、配置位置更新与持久化。配置模式和渲染模式最终共用 `MoveCharacter` 位置管线，不复制坐标算法。

### 动画角色约定

- `idle`：渲染待机。
- `action`：短按互动。
- 其他动画：拖动候选池。

拖动期间每次只随机一次并循环，不在移动过程中连续切换。动画名匹配 `idle` 和 `action` 时不区分大小写。

### 配置兼容

- 将代码语义从 `CurrentAnimation` 明确为 `ConfiguredAnimation`，但 JSON 仍读取/写入旧键 `CurrentAnimation`，避免破坏现有配置。
- 新增每角色 `AnimationSpeed`，缺失或非法值迁移为 `1.0`。
- 新增全局 `AllowRenderDrag`，旧配置默认启用。
- 配置版本更新为 `1.1`。

## 实施阶段

### 阶段一：统一模式和运行状态

- 用一次全局 `SetConfigMode` 取代逐角色 `SetCharacterConfigMode`。
- 模式消息携带每个角色的配置动画映射。
- 修复托盘“显示全部”错误切换到配置模式的问题。

### 阶段二：渲染拖动

- 扩展低层 Hook，处理左键按下、移动、抬起。
- 为每次按下分配会话 ID，防止异步 JS 命中结果串到下一次操作。
- 使用系统拖动阈值区分点击和拖动。
- 拖动过程中限制位置更新频率，避免高频 WebView 消息。
- 松手后保存最终坐标并通知 UI 刷新。

### 阶段三：设置和持久化

- 在配置面板增加“Allow dragging in render mode”开关。
- 速度滑块读写选中角色的 `AnimationSpeed`。
- 新增配置归一化和向后兼容迁移。

### 阶段四：删除旧代码

删除确认无调用者的内容：

- JS `activeSingleCharacterId`。
- `load`、`play`、`setScale`、`setSpeed` 旧单角色消息。
- Canvas 右键动画菜单。
- `PrimeHiddenWindowsAsync` 空占位。

保留：

- `TexturePath`：面板角色缩略图仍在使用。
- `AdditionalTexturePaths`：代码使用明确命名，JSON 继续使用旧键 `ExtraTexturePaths` 以兼容现有配置。
- 配置模式 Overlay：它承担精确编辑，与渲染模式拖动用途不同。

## 验收与回归

- JavaScript 语法检查。
- C# Debug、Release 构建，要求 0 警告、0 错误。
- 模拟 WebView/PIXI 测试：
  - 点击与拖动阈值互斥。
  - 拖动动画候选不包含 `idle`、`action`。
  - 拖动结束返回 `idle`。
  - 模式切换恢复配置动画。
  - 速度映射与持久化正确。
- 配置迁移测试：
  - 旧 `CurrentAnimation` 无损读取。
  - 缺失速度迁移为 1.0。
  - 角色路径保持大小写不敏感去重。
- 确认临时测试文件、测试进程和测试角色均无残留。
